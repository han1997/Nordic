# 全页面 UI 统一与精细化完善

## 原始目标（不缩小）

对每一个页面进行最精细化的 UI 统一、完善，不要有割裂感。

本任务覆盖整个 Nordic Android 应用，不以“几个页面”“几个设计 token”或“通过少量测试”代替目标。多轮逐步推进，所有可达页面、子页面、弹层与关键状态均需有可追溯的审查和验证证据。

## 当前阶段

用户回复“继续”，开始实施首批共享基础统一；已建立 37 个页面/面板分组的覆盖矩阵，后续继续逐页落实与验证。之前的视频播放器任务已归档，不把其已有成果或测试当作全应用完成证据。

## 已知约束

- 技术栈：Kotlin / Jetpack Compose / Material 3；业务域为音乐、有声书、视频、服务器配置。
- 基线提交：4774a19；工作区仅有用户原有 gradle.properties 修改，不覆盖或提交该修改。
- 保留现有 Nordic 品牌、媒体服务协议和功能；统一不等于把不同媒体硬塞进同一种页面布局。
- 上一任务已有视频离线预览，但全应用尚无完整截图/交互回归体系。物理设备可能正在用于其他应用，未经确认不抓取或操作非测试界面。
- 既有全量测试曾卡在 EncryptedConfigStoreTest 的配置更新用例；这不应被忽略或包装为全套测试通过。
- 项目永久禁用子代理，本任务全部由主会话推进。

## 设计方向与工作假设

- 延续 Nordic 的冷静紫/青强调色、清晰中文字体和克制的动效，先统一语义与层级，不进行无依据的换品牌/换框架。
- 页面共用一致的导航、内容边距、标题/说明层级、列表密度、封面圆角、操作尺寸、分段筛选和反馈规则。
- 观影的深色沉浸背景、专辑方封面与影片海报比例等内容差异保留；组件语言与操作逻辑需要一致。
- 先审查真实代码/现有规范，能从仓库得出的内容不反问用户；发现真正影响产品方向的歧义再单独确认。

## 完整需求

1. **所有页面与状态**：覆盖音乐首页/库/搜索/收藏/专辑/歌手/歌单及其详情、三类播放器及附属面板、有声书书库/详情、视频媒体库/详情、配置页面和应用级导航。
2. **视觉合同**：统一颜色和表面层级、文字与数字排版、尺寸/间距/圆角、图标、阴影/边框以及加载/空/错误/成功/禁用/选中状态。
3. **交互合同**：统一返回、关闭、菜单、刷新/重试、表单验证、列表点击、按钮反馈与面板展开；保留可达性和原有业务能力，不放空按钮。
4. **适配与无障碍**：浅/深主题、小屏/横屏/大字体、系统栏/刘海/键盘安全区；可点击目标、中文语义、对比度及长文本/缺失图片稳定性。
5. **技术一致性**：重复模式优先收敛为共享组件/语义 token；不机械替换掩盖差异，不引入无依据的依赖，不破坏媒体切换、播放进度与性能合同。
6. **逐页证据**：维护 research/ui-coverage.md，记录每个页面/面板的问题、改动、测试、渲染/交互证据与未完成项。
7. **最终验收**：完整页面矩阵、关键状态及两种主题均被覆盖；编译、合理范围的自动测试/lint/打包通过，视觉和交互证据足以支撑无割裂感结论。

## 推进顺序（不是缩小范围）

- 阶段 A：完整审查与统一标准；共享组件/基础 token、应用导航与状态反馈先收敛。
- 阶段 B：音乐所有页面和操作面板逐一打磨。
- 阶段 C：有声书、视频所有浏览/详情/播放页面与面板逐一打磨。
- 阶段 D：配置表单、错误/空/加载状态、浅深主题和适配回归；建立并执行全页面视觉/交互验证。
- 阶段 E：对照完整目标独立完成审计；只有每项均有充分证据才结束线程目标。

## 明确不做

- 不引入新的媒体服务、广告/社交流或无关后端功能。
- 不假装精细化可以只靠批量数值替换完成。
- 不把真实设备中的其他应用作为截图/点击测试对象。
- 不因为当前轮次或单次工具限制而删除原始范围、提前标记目标完成。
