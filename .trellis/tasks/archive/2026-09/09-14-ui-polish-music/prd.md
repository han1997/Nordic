# 全应用 UI 精修第二轮：音乐域页面与弹层收口

## 目标与承接

用户在首轮样板方向确认、55 文件提交及归档后要求“继续下一轮”。本轮沿用已确认的紫/青品牌、深浅主题、原生字体、均衡密度与导航，不重新选风格。按完整音乐域相邻页面批次推进，而不是跨域零散改控件；全应用目标仍保留，其他域后续分别逐页验收。

基线 main / c1ee241（工作提交 a889a1b），应用 0.1.9 / 9；712 JVM。开始时工作区干净；专用 nordic-ui-api34 / emulator-5580 已存在，不操作个人手机。

## 范围

- 未完成的音乐浏览页面：发现、专辑列表、歌手列表、歌手详情、搜索、歌单列表、歌单详情。
- 音乐集合与播放器附属交互：新建/重命名/删除歌单、收藏与下载操作层；均衡器只审查/修整现有未接入组件，不能计作真实可达或音效验收。“加入歌单”无 UI，仅保留缺口，不在视觉任务新增业务。
- 首轮歌曲、专辑详情、播放器/歌词/队列/倍速与 Dock 做共享影响回归，不能靠回归数量冒充新增页面。
- 对每个实际存在的加载、空白、错误/重试、无封面、长文本、编辑/禁用/提交状态分别记录。不存在的状态不造假计数。

## 方案取舍

- 采用“音乐域闭环”：可直接复用首轮已确认 tokens、宿主隔离与模拟器底座，减少跨域打断，同时完成该域未验页面和弹层。
- 不采用“只改测试/截图”或“几个易改组件”：须先看实际渲染和源码，修整真实生产界面；不是仅增加样例。
- 不一次混入有声书/视频/所有设置：仍属于全应用后续批次，不宣称本轮覆盖。

## 实施关卡

1. 逐页审计源码/入口、列出具体问题及状态矩阵，复用生产 UI 扩展 Debug 样例；必要时只抽取无副作用内容层。
2. 修改视觉前保存本轮严格基线：同模拟器/分辨率/系统字号/主题/数据，记录源码、Debug/测试 APK 和每张图指纹。不得覆盖首轮封存证据。
3. 改进内容层级、列表/卡片间距、管理动作可发现性、窄屏/大字号/IME 可达性与语义，保留真实业务回调、缓存/来源隔离、播放/歌单协议。
4. 逐页截图与自动交互验证，补新增布局/回调回归；若源码变化，旧证据不能冒充最新。
5. 更新 DESIGN/CHANGELOG/必要 README 与规范，产出本轮前后图及覆盖索引；用户确认一次工作提交清单后才提交，不 push。

## 验收标准

- [ ] 上述 7 个未验音乐页面和音乐专属弹层都有真实生产入口、对应 Debug 样例/交互、逐页结论，非复制展示版 UI。
- [ ] 本轮严格同条件前后证据可追溯；双主题、360dp 字号 1/2、320dp 短屏/2×，补 392dp/1.5× 与 720dp/2× 的实际布局检查。

- [ ] 筛选/导航/播放/集合管理/均衡器/下载回调不丢失；不构造真实账号、服务或持久化样例。
- [ ] 编译、完整 JVM、Lint、Debug/Release/测试 APK、专用模拟器 UI 测试通过；验证 0.1.10 / 10、签名延续、Release 无目录/资源、实际 Retrofit DEX 泛型。

## 明确不在本轮
