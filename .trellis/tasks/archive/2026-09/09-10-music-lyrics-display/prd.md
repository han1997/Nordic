# 音乐歌词显示逻辑优化

## 目标与用户确认

按已确认计划优化完整显示、同步跟随和切歌加载，不更换视觉风格或歌词来源。

- 播放中：手动拖动及惯性滚动结束 2 秒后恢复跟随，再次操作重新计时。
- 暂停时：保留浏览位置；继续播放恢复跟随，正在拖动时不抢占操作。
- 本次使用期间记住歌词/封面选择，包括切歌、收起重开；应用重启默认封面。

## 实现合同

1. 普通/同步歌词使用完整可滚动列表，不截断前 5～7 行或单句两行；时间戳稳定排序，同时间不同文本组成句组共同高亮，同时间同文本去重；未计时正文置于同步内容之后，纯普通歌词保留顺序与重复段落。
2. 保留毫秒及既有 offset 正负语义，首句之前不高亮。两个来源共用领域规范化与活跃句定位，不为 UI 重复过滤/截取正文。
3. 自动跟随按实测行高/可视区域居中，首尾留白，超高句顶部对齐；正常换句平滑，切歌/重开/主动 seek 直接定位。手动与程序滚动分开，回到当前按钮可立即恢复；离开视图取消定时器。
4. 保留单击切换和双击快进退；新增按钮/滚动不误触父手势；高频进度只在同步歌词叶子订阅。
5. ViewModel 使用带歌曲标识的单一 MusicLyricsUiState；按仓库身份、歌曲 ID 和兜底查询元数据去重，切歌/配置变更取消旧任务，迟到结果不能覆盖新歌；收藏变化不重取。
6. 保留歌曲 ID 优先、歌手标题兜底；取消异常传播，成功空结果与加载失败分开。仅可重试的错误提供重试，加载中不重复发起，无服务器配置不能无效重试。
7. 移除仅被测试引用的旧窗口截取辅助函数，测试改为真实领域/跟随状态行为。

## 边界与交付

不新增双语选择、逐字、点词跳播、新歌词来源或持久歌词缓存；不改服务器协议。版本 0.1.2/2 → 0.1.3/3，包名/签名/R8 保持。真机拖动、排版和主题需单独验收；本轮未自动卸载应用或清除数据。

## 已知实现现状

- MusicPlayerScreen：普通歌词只取 5/7 行、Text maxLines=2；同步列表只在当前行出视口后滚动；showLyrics 随 song.id 重置。
- MusicPlaybackViewModel：三个独立歌词 StateFlow；onEach 串行加载且按整个 Song 比较。
- NavidromeRepository：getLyrics 的 runCatching 吞掉异常和取消；结构化歌词未排序，先按 synced 标记选候选再解析。
- MusicScrollbar 只显示，不提供拖动交互；无需改动共享滚动条。
- 已有毫秒、offset、nullable lyrics wire 数据测试必须保留。
