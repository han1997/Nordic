# UI 与逻辑继续优化

## Goal

在上一轮播放器与 Dock 交互稳定性修复的基础上，继续优化 Nordic Media Hub 的媒体浏览体验和页面状态逻辑。重点从音乐、有声书、视频三类浏览页的加载、缓存、筛选、详情和错误反馈中找出仍会造成困惑或状态残留的问题，并用现有 Compose 设计系统和测试体系进行收敛。

## What I Already Know

* 项目是 Android Jetpack Compose 单仓库应用，包含 Navidrome 音乐、AudiobookShelf 有声书和 Emby 视频。
* 上一轮已完成严格单媒体播放交接、关闭失败保护、视频从头播放交接、Dock 手动隐藏恢复和相关回归测试；本轮不重复修改这些已完成行为。
* 音乐页面使用多个独立加载状态和详情导航状态；有声书和视频页面使用缓存优先、TTL 刷新、配置切换重置和局部错误提示。
* 三类页面已经共享 `MediaPageHeader`、`MediaStateCard`、`MediaLoadingCard` 等组件，但部分状态文案、列表稳定性和错误/缓存分支仍需要一致性审查。
* 现有测试覆盖 `MusicScreenV2`、`AudiobookScreen`、`VideoScreen`、播放器和队列逻辑；应优先增加纯函数测试，降低 UI 回归风险。
* 设计约束是内容优先、轻量透明层、统一的 Nordic token，不进行无关的全量视觉重构。

## Assumptions (Temporary)

* 本轮默认主攻三类媒体浏览页的 UI 状态与逻辑一致性，而不是播放器底层或新的服务接入。
* 优先修复能够从代码和现有测试直接确认的状态问题，再处理用户偏好的视觉细节。
* 缓存优先策略继续保留，优化目标是让缓存、刷新、失败和配置切换的反馈更准确。

## Open Questions

* 无阻塞性范围问题，待最终确认后进入实现。

## Requirements (Evolving)

* 审查音乐、有声书、视频页面的加载、缓存、空状态、错误、筛选和详情状态，避免旧状态残留或用户无法判断当前数据来源。
* 本轮主攻状态逻辑一致性，UI 调整仅服务于表达状态和提供下一步操作。
* 保证配置切换、手动刷新和缓存命中/过期时，列表、选中项、筛选条件、加载状态和提示文案同步更新。
* 统一三类媒体的状态卡片、页面副标题、刷新反馈和空状态引导，继续使用共享组件和设计 token。
* 检查媒体列表 LazyColumn/LazyRow/LazyGrid 的稳定 key、contentType、预览数据与播放数据边界，避免重组抖动和错误点击索引。
* 对修复过的纯逻辑、状态转换和边界条件补充回归测试，并保持上一轮播放器/Dock 行为不回退。
* 配置切换或媒体库切换必须清理旧账号/旧媒体库的内容状态，异步旧请求不得回写新配置页面。
* 配置/账号切换时立即清理旧配置的内容、详情、筛选、错误和加载状态；不得用旧内容占位等待新配置请求。
* 同一配置的手动或 TTL 刷新期间保留当前缓存内容，并通过副标题或状态提示表达“正在刷新”。
* 新配置若有其自身缓存则先显示该缓存再刷新；刷新失败时继续显示该配置缓存，并展示明确错误，不回退到旧配置内容。
* 详情页刷新后当前条目消失时，自动返回对应列表，保留刷新后的列表内容，并显示一次轻量说明；不继续展示过期详情。
* 三类媒体刷新失败统一采用“保留缓存 + 页面副标题提示”；无缓存时显示共享独立错误卡片。

## Acceptance Criteria (Evolving)

* [ ] 缓存、刷新、失败和未配置状态在三类媒体页面上均能准确表达当前状态，并提供可执行的下一步操作。
* [ ] 配置切换或媒体库切换后，不再显示旧账号/旧媒体库的详情、筛选、列表或错误状态。
* [ ] 手动刷新期间已有缓存内容不会被无意义的空白加载态覆盖，失败时仍保留可用缓存并显示明确反馈。
* [ ] 配置切换过程中不会短暂显示上一配置内容；新配置刷新失败时只保留新配置自己的缓存。
* [ ] 刷新导致当前详情条目失效时，页面返回正确列表并只显示一次可理解的原因说明。
* [ ] 有缓存的刷新失败不清空内容且通过页面副标题表达失败原因；无缓存失败显示独立错误卡片。
* [ ] 列表和网格使用稳定身份，点击播放或打开详情不会因重复条目、列表刷新或预览切片导致错误索引。
* [ ] 视觉修改遵循现有 Nordic 色彩、形状、间距、动效和共享状态组件规范。
* [ ] 相关单元测试、Kotlin 编译和 Android lint 通过。

## Confirmed Scope

* 主攻范围：三类媒体浏览页的状态逻辑一致性。
* 包含：缓存命中/过期、手动刷新、网络失败、未配置、配置切换、媒体库切换、筛选清理、详情选中项和异步请求过期保护。
* UI 只调整状态副标题、共享状态卡片、加载反馈和错误引导等必要部分。

## Decision (ADR-lite)

**Context**: 清空所有刷新内容会产生明显闪烁，而跨配置保留旧内容会造成账号/服务器数据归属错误。

**Decision**: 配置切换立即清理旧内容；同一配置刷新保留当前缓存；新配置只允许展示按新配置 key 读取到的缓存。

**Consequences**: 首次连接或新配置无缓存时会显示正常加载/空状态，但不会把旧账号内容误标为新账号内容；常规刷新则保持内容连续可读。

## Confirmed Detail Behavior

* Music、Audiobook、Video 在刷新后发现当前详情条目不存在时，都返回对应列表层。
* 返回后保留刷新成功的列表数据，并显示一次轻量状态说明。
* 详情页不继续使用失效对象渲染或提供播放入口。

## Confirmed Error Presentation

* 有缓存时：继续显示缓存内容，页面副标题显示“正在显示上次缓存：原因”。
* 无缓存时：显示共享 `MediaStateCard` 错误卡片，提供刷新或前往配置等下一步操作。
* 错误提示属于当前配置和当前媒体页面，不得显示旧配置请求产生的错误。

## Definition of Done

* 完成确认范围内的浏览页 UI/逻辑优化。
* 为状态转换和发现的回归问题补充测试。
* 通过 `:app:compileDebugKotlin`、`:app:testDebugUnitTest` 和 `:app:lintDebug`。
* 用户可见行为变化同步更新 `CHANGELOG.md`；若形成新的稳定实现约定则更新 `.trellis/spec/`。

## Out of Scope

* 不新增媒体服务或修改 Navidrome、AudiobookShelf、Emby 的认证协议。
* 不重写 Media3 播放引擎、跨媒体交接流程或底部 Dock 规则。
* 不进行与状态一致性无关的全量页面视觉重构。
