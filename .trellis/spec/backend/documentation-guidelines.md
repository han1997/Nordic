# 中文化沟通与文档更新规范

> 适用于 Nordic Android app 的开发沟通、用户可见文案、项目文档、任务材料和发布记录。

---

## 总原则

项目协作和项目文档默认使用中文。新增或修改内容时，优先让用户、开发者和后续 AI 代理能用中文理解变更目的、使用方式和影响范围。

保留必要技术原名，不为了中文化牺牲准确性。代码标识符、类名、函数名、API 字段、第三方库名、协议名、文件路径、命令、HTTP endpoint、异常类型和英文错误枚举保持原名。

---

## 中文优先范围

以下内容应使用中文，除非引用外部规范或代码原文：

- 与用户的开发沟通、实现汇报、检查结论和剩余风险说明。
- 用户可见 UI 文案、空状态、错误提示、按钮标签和设置说明。
- Trellis 任务材料，包括 `prd.md`、`info.md`、研究记录、实现/检查记录和归档说明。
- 项目文档，包括 `README.md`、`CHANGELOG.md`、使用说明和配置说明。
- 提交说明、PR 描述和发布说明；如果仓库历史有固定英文前缀（如 `docs:`、`fix:`），前缀可保留，正文使用中文。

允许保留英文的内容：

- Kotlin/Java 包名、类型名、函数名、变量名、测试名和资源标识符。
- Navidrome、AudiobookShelf、Emby、Subsonic、OpenSubsonic、Media3、Retrofit、OkHttp、DataStore 等产品、协议和库名。
- API 参数、JSON 字段、HTTP 路径、Gradle task、shell 命令和文件路径。
- 第三方错误码、英文异常类型、日志 tag，以及必须与外部系统精确匹配的字符串。

## CHANGELOG.md 更新规则

每次变更都要判断是否需要更新 `CHANGELOG.md`。满足以下任一条件时必须更新：

- 新增、删除或改变用户可见功能。
- 修改用户可见行为、导航流程、配置方式、错误提示或空状态。
- 修复会影响用户体验、数据展示、播放、同步、认证或兼容性的缺陷。
- 修改构建要求、依赖、权限、最低系统版本、服务接入方式或缓存/数据迁移语义。
- 新增或调整开发规范、协作约束、质量门禁或文档维护规则。

更新方式：

- 使用中文描述，放在顶部最新版本或 `未发布` 区块。
- 按现有结构归类，例如 `新增`、`改进`、`修复`、`文档`、`开发规范`。
- 记录用户或维护者需要知道的结果，不写实现流水账。

以下情况通常不需要更新 `CHANGELOG.md`：

- 纯内部重构，且没有用户可见行为、构建方式、配置方式或兼容性变化。
- 只调整测试、格式化、注释或无行为变化的本地实现细节。
- Trellis 任务过程文件、临时研究记录或会话日志变更，且不改变项目规范或用户文档。

## README.md 更新规则

`README.md` 面向新用户和维护者，只有当项目使用方式或关键信息变化时更新。满足以下任一条件时必须更新：

- 新增或移除主要能力、服务集成、播放能力、同步能力或用户入口。
- 改变安装、构建、运行、权限、最低 Android/API 版本或 Android Studio/Gradle 要求。
- 改变服务器配置项、认证方式、必填/可选字段、示例地址或服务限制。
- 新增用户必须知道的限制、兼容性说明、数据缓存/同步语义或故障排查步骤。
- 文档当前描述已经与实现不一致，且本次变更触碰相关功能。

以下情况通常不需要更新 `README.md`：

- 小型 bug 修复，没有改变使用方式或项目能力描述。
- 内部代码结构、测试、开发规范或实现细节变化，不影响用户理解和使用。
- 已由 `CHANGELOG.md` 记录即可的单次修复或微调。

## 检查清单

- [ ] 用户可见文案和项目文档优先使用中文。
- [ ] 技术专有名词、代码/API 标识符和外部协议字段保持准确原名。
- [ ] 符合触发条件的变更已更新 `CHANGELOG.md`。
- [ ] 影响安装、配置、使用、能力或限制的变更已更新 `README.md`。
- [ ] 不需要更新 `CHANGELOG.md` 或 `README.md` 时，能说明原因。
